# Scamwin browser extension pilot

This is an unpacked Manifest V3 pilot for Chrome/Edge. It has no store dependency, paid service or publisher fee. A Chrome Web Store release is a separate decision; an authorized unpacked/Edge pilot is the current ₹0 path.

## Install and pair

1. An operator must first configure the isolated connector database, application encryption keys and the connector/extension flags, then complete the app integration and connector schema review. Do not run DDL against the main database. See the project connector setup instructions.
2. Open the browser's Extensions page, enable developer mode, choose **Load unpacked**, and select this `extensions/scamwin` folder. Pin its action. No broad website permission is granted on installation. The one fixed application origin permission allows delivery to `https://scamwin.vercel.app`; it is never a capture source.
3. In the extension popup, choose **Create pairing ticket**. Copy that ticket into **Connected apps → Browser extension** in your signed-in Scamwin session. Only approve a ticket just generated by your own extension. Choose Manual, Selective automatic or All new visible pages, exact site origins, and processing consent.
4. The authenticated app displays a five-minute, one-use approval code. Copy it back into the same extension popup and choose **Finish pairing**. Never send your ticket/code to another person. No Auth0 credential is copied into the extension. Opening a forwarded link does not approve or pair anything.
5. For a manual check, open a public page, click the extension action and choose **Check visible page**. For automatic checks, first approve an exact site in the app and then, while on that site, click **Allow checks on this site** in the popup. Accept the browser's exact-origin permission prompt. Each site requires a separate gesture; wildcard monitoring is not enabled.

Pairing uses a locally generated 256-bit verifier, its SHA-256 challenge and the extension ID. Only the signed-in action issues the approval code. Redemption requires both that code and the local verifier; there is no anonymous polling endpoint. The bearer grant stays in trusted extension storage, is never returned to page/content scripts or exposed by status messages, and is stored only as a hash on the server. Grants expire after 30 days and are bound to the connection owner, epoch and extension ID. Settings changes, account erasure or disconnect invalidate intake. There is no custom-server setting, redirect following or page-message configuration bridge.

## Coverage and limits

- Captures contain bounded visible top-frame DOM text and public HTTP(S) destinations. Inputs, textarea/select values, forms/payment fields, editable areas, hidden content, scripts, other frames and images are excluded. Text outside the visible viewport, shadow content and unsupported elements may be missed. Every source is honestly marked partial.
- Manual permission is temporary `activeTab` plus `scripting`; automatic collection uses separately requested optional exact-site permissions. All new visible pages applies no hidden suspicion/sender filter. Selective mode uses the phrases the owner supplied. An explicit manual click can check a page that did not match those phrases.
- Automatic attempts happen on a completed navigation, tab activation, or focused-window change. They recheck the active tab, focused window, visible document, saved site scope and current browser permission before delivery. This is not a continuous DOM observer, inbox reader, history feed or guarantee that every page edit is seen.
- The app's own hostname is excluded to avoid inspecting generated results repeatedly. Use the normal New check form for a manual check originating there. Private/reserved origins, credentials in URLs and custom ports are rejected. Page destinations are validated again server-side; subsequent collectors maintain their own DNS/egress checks.
- Browser closure, MV3 suspension, hidden tabs, offline periods and permission removal cause gaps. No private page body is queued to disk or replayed later on a new origin. Local storage holds only pairing/grant data, approved site origins and bounded delivery status. The popup shows failed delivery/removal and requires a fresh current-page capture.
- Delivery saves encrypted source evidence and a durable preparation in the connector database, not a direct main check. Shared preparation, dedupe, quotas, admission, runner and suppression apply. Existing main limits remain 10/day and 50/month; automatic limits remain 8/day and 40/month globally, 1/day per owner by default (maximum 2) and one concurrent automatic run. A saved source is not a completed investigation.
- Text is capped at 256 KiB, destinations at 200 including the page URL, capture age at 60 seconds, pairing at five minutes. Bodies expire within 30 days and event metadata within 90 days. This extension sends no images or attachments.
- **Unlink this browser** stops collection and removes requested site permissions immediately. If offline, server revocation remains pending and can be retried. App-side disconnect also fences intake immediately. An obsolete grant can be discarded without revoking a newer connection epoch. Changing scope/mode requires unlinking and pairing again.

## Operator integration

The server factory is `createExtensionIntegration({database, keyring, environment, now?})`; `database` must be the guarded isolated connector database. It returns `{configuration, service, adapter}`. Register the service with `registerExtensionService`, mount `ExtensionConnectionSetup` inside the existing Connections page, import `scamwin-extension-schema.ts` into the connector schema aggregation, and include `service.purge()` in retention. No main schema change or migration is involved.

POST endpoints under `/api/scamwin/connectors/extension/`: `redeem`, `intake`, `gap`, `revoke`. Requests have JSON content type and `X-Scamwin-Extension` with the actual extension ID. Except for one-use redemption they require the private Bearer grant. These endpoints do not accept a browser owner identifier or cookie-based authorization. Only `approveExtensionPairing` uses the Auth0 web session. Service registration is lazy in the shared integration module.

## Repeatable checks and live gates

Run `node --import tsx --test tests/scamwin-extension.test.ts tests/scamwin-extension-browser.test.mjs` for SQL pairing/epoch/erasure/replay/input/HTTP checks and controlled browser-event/permission/navigation/offline tests.

`node scripts/check-scamwin-extension.mjs` launches Playwright's bundled Chromium with this actual unpacked artifact in a fresh task-local profile. It intercepts a synthetic page, verifies the real isolated-world collector, malicious-message rejection, narrow popup rendering and genuine native-action popup ticket creation, and writes screenshots under the task SDD artifacts. It uses no user browser profile, app login, production source or provider account. If necessary set `PLAYWRIGHT_BROWSERS_PATH` to an existing test cache. In this task it was `.superpowers/sdd/2026-11-10-scamwin-connected-apps/task-12c-browser-cache`. Do not package that browser cache/profile with the extension.

Still required before enabling a pilot: real Auth0 pairing through the mounted app, genuine toolbar `activeTab` click, exact-site permission prompt acceptance/denial/removal, navigation during collection, focused/hidden/closed-browser behavior, server disconnect/erasure, quota deferral and a source reaching a private result. Synthetic tests do not constitute real-account consent or store-release acceptance. Current documentation: [activeTab](https://developer.chrome.com/docs/extensions/develop/concepts/activeTab), [optional permissions](https://developer.chrome.com/docs/extensions/reference/api/permissions), [trusted storage](https://developer.chrome.com/docs/extensions/reference/api/storage), [Playwright unpacked extensions](https://playwright.dev/docs/chrome-extensions).
