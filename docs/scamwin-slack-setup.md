# Slack connector operator setup (Task11A, default off)

This module supports a confidential Slack app installation and explicitly selected bot-visible conversations. It does not connect the installer's whole Slack inbox. It requests public-channel `channels:read,channels:history` by default; the driver can explicitly configure matching private-channel, bot-DM or group-DM read/history pairs. No join, send, write, delete or admin scope is requested. Optional `files:read` is requested only with `SCAMWIN_SLACK_FILES_ENABLED=true`.

Keep Slack's irreversible public-client/PKCE setting OFF for this confidential app. Configure a Web redirect exactly as `APP_BASE_URL/api/scamwin/connectors/expanded/slack/callback`. `APP_BASE_URL` must be a trusted HTTPS origin with no path/query/credentials. There is no browser-supplied redirect setting. Code exchange uses fixed `https://slack.com/api/oauth.v2.access`; `auth.test` verifies the returned bot, team and workspace host. The stable identity is app+workspace+verified installer; email is not an identity key.

Server-only environment: `APP_BASE_URL`, `SCAMWIN_SLACK_CLIENT_ID`, `SCAMWIN_SLACK_CLIENT_SECRET`, `SCAMWIN_SLACK_APP_ID`, `SCAMWIN_SLACK_SIGNING_SECRET`; optional `SCAMWIN_SLACK_FILES_ENABLED`. Canonical operator gates are `SCAMWIN_CONNECTORS_ENABLED`, `SCAMWIN_CONNECTOR_SLACK_ENABLED`, `SCAMWIN_CONNECTOR_AUTOMATION_ENABLED`. All default off. Automatic capability additionally requires `SCAMWIN_SLACK_COVERAGE_PILOT_ACCEPTED=true`, which is an operator assertion only after the pilot below, not evidence supplied by synthetic tests. No real configuration was changed in this task.

Configure signed Events API delivery at `/api/scamwin/connectors/slack`; subscribe only the granted conversation classes. Request signing validates original bytes and five-minute timestamp freshness. The webhook validates app/workspace, selected resource and current epoch, deduplicates durable event IDs, and stores encrypted references only. Manual/paused deliveries retain content-free metadata/gaps. New bot-authored messages are included in All. Edits fetch the latest accessible revision; if that differs from the queued revision, coverage explicitly reports `slack_intermediate_revision_unavailable`. Deleted source tombstones share Core's connection lock and suppression tables, including delete-before-create, so late reads cannot recreate private content.

Subscribe to `app_uninstalled` and `tokens_revoked` as well. Authenticated uninstall notifications disconnect every matching saved app/workspace installation locally; bot-token revocations match the saved bot **user** ID, while unrelated and user-token revocations do not revoke the bot grant. The disconnect transaction fences old work and erases local credentials before acknowledgment, without uninstalling or revoking a shared Slack installation remotely. Lifecycle IDs persist across reconnect epochs for retry deduplication. Verified OAuth identity records its authorization time; notifications from earlier seconds cannot revoke a later authorization. Slack timestamps have one-second precision, so ordering within the same second is treated conservatively as revocation. See [Slack uninstall events](https://docs.slack.dev/reference/events/app_uninstalled/) and [revoked-token identities](https://docs.slack.dev/reference/events/tokens_revoked/).

The authorization transaction writes installation routing together with the verified identity and grant under the owner-generation fence. Lifecycle notifications therefore route immediately after OAuth completes, before conversation discovery or selection. A routing write failure rolls back the entire attachment.

Top-level `app_rate_limited` notifications persist one bounded `slack_event_delivery_rate_limited` gap per app/workspace/minute before acknowledgment and bring an existing recovery schedule forward. They do not claim that history recovers every missed edit, deletion or reply. Slack documents this [separate notification envelope](https://docs.slack.dev/reference/events/app_rate_limited/).

Manual selection uses a pasted message permalink, not recent-message browsing. Slack has no metadata-only message list suitable for this flow; `listSelected` is deliberately absent. The backend verifies the exact workspace host from `auth.test`, the selected authorized channel, current membership and actual read scopes, then requests that message from a fixed Slack API method. It never fetches the pasted web URL or sends the permalink to AI. Thread links use the fixed replies endpoint; unavailable bot thread access remains unavailable. The link stays in the form on rate limits and the response contains a safe retry duration.

Recovery uses a post-activation bounded history page (15 items) with opaque provider page cursor persisted alongside the durable Core pending references. Inclusive time boundaries intentionally overlap; Core deduplication prevents duplicate checks. Each app/workspace/method shares one durable request/minute budget. Local exhaustion reports `runtime_quota_paused` so the existing worker does not spend body-retry attempts; its current conservative scheduling can defer longer than one minute. Actual 429 Retry-After extends the durable deadline. History is not a full reply archive; `slack_thread_recovery_unavailable` remains an explicit gap. Throughput and backlog retention require pilot measurement before automatic enablement.

Delivery deduplication metadata is separate from pending-reference capacity. Manual, completed and previous-epoch deliveries do not impose a 1,000-message lifetime ceiling. Once Core durably saves the event cursor, later intake clears the handed-off reference payloads while preserving delivery IDs and deletion tombstones. Intake counts current queued Slack references alongside Core owner backlog; a full backlog persists a single `slack_event_backlog_capacity` warning and returns non-success for retry without advancing the unsaved event. Successful intake after draining records `slack_event_backlog_recovered`.

Files require `files:read`, current selected-channel membership, matching file shares for the exact message, Slack hosted mode, and a verified workspace/file path on `https://files.slack.com/files-pri/`. External files and redirects receive no bearer token. Downloads honor a ten-second overall deadline and the existing target byte budget; files older than seven days are unavailable. Supported raster targets use the existing private preparation pipeline. Text/context remains Core's 30 days; historical delivery metadata and unused discovery handles expire after 90 days. Current installation routing and selected resource handles follow the saved authorized connection lifetime, with membership/scope revalidated before provider body access. `SlackStore.purge()` renews only that current authority, preserving opaque handles, and deletes expired historical metadata. Disconnected or grantless authority receives no renewal. Root maintenance must call `SlackStore.purge()`.

Generic isolated connector maintenance preserves that same current Slack authority before deleting expired supplemental rows, including when connector gates and provider configuration are off. Historical deliveries and unused handles still expire through that credential-free path.

Disconnect locally fences jobs and erases the grant first. Common `prepareDisconnect()` captures locally only and refuses remote cleanup before fencing. Slack intentionally never revokes the token or uninstalls the app, because the workspace installation can be shared. The owner/admin removes the Slack app through Slack when appropriate. A single Scamwin owner disconnect must not disrupt another owner.

## Root13 composition (required before readiness)

- Register a trusted factory with `registerExpandedAuthorizationServices(() => ({service,persistence}))` in `expanded-server.ts`. Use the isolated ConnectorDB factory, Core store/keyring, metered transport, and the fixed `slackAuthorizationDriver()`; later providers supply their own drivers. Shared begin action and callback route already call this factory.
- Construct `createSlackIntegration({core,database,keyring,runtime,authorization,persistence,fetch,environment,now})`; register `.adapter` through `registerConnectorProvider('slack', factory)` and the returned services with `registerSlackServices(factory)`. No provider registration occurs as an import side effect.
- Add all four exports of `lib/db/scamwin-slack-schema.ts` to the isolated connector schema/config. Do not apply DDL or touch the main database during integration review.
- Mount `SlackConnectionSetup` on the existing connection card and `SlackManualSelection` for Slack Manual intake. Supply only the safe app connection ID/epoch, readable labels and opaque handles; no Slack IDs/cursors/grants go to the browser.
- Root13 owns Account readiness, expanded disconnect dispatch, canonical automation gate alignment, purge wiring, aggregate tests and desktop/mobile browser checks. No claim of deployed/composed readiness is made here.
