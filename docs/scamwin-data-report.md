# Scamwin data foundation

Implemented typed domain contracts and shared browser/server intake validation, 14 Drizzle tables re-exported by the existing schema entry, explicit MemoryStore injection for tests, and a Neon HTTP PostgresStore. Production configuration requires DATABASE_URL; missing configuration never selects memory. Worker code imports repository-core; web code uses the server-only repository wrapper. SCAMWIN_ADMIN_SUBJECTS supplies exact trusted bootstrap subjects on the server.

Private ownership and expiry are checked on reads and writes. Intake screenshots live in expiring artifact rows; persisted input JSON holds metadata and artifact IDs. Hydration returns bytes only before seven-day expiry. Check inputs are immutable. Admission atomically inserts the check, run, input artifacts and durable outbox entry. A first-statement advisory lock followed by an explicit READ COMMITTED statement protects global 10/day, 50/month, owner 3/day and one-active-run limits across instances; durable reservations survive deletion. Revision/generation checks fence claims and updates. Cancellation blocks subsequent result writes; deletion hides private data, clears private content and withdraws unleased review/publication work.

Artifacts enforce four inputs/three captures, validated raster signatures, 160 KiB each, a 200 MiB global cap, ownership and seven-day expiry. Follow-up messages and evidence citations are bounded. Warning consent binds a canonical public-payload hash and revision to an independent seven-day evidence snapshot. Publication eligibility requires a selected matching hostname and observed live-page, origin-probe or registry evidence; submitted text alone is insufficient. Role-enforced review uses revision CAS and writes local reviewed warnings, publication operations, outbox entries and sanitized audit rows atomically. Local warnings expire after seven days and queued status never claims chain confirmation.

Outbox leases are exclusive and attempt-fenced. Publication leases share the review/deletion lock and serialize the signer. A pending uncertain signed transaction prevents another unsigned operation from acquiring a nonce. Signed bytes/hash/nonce persist together before broadcast, remain immutable and are private. Signing requires the current fenced lease and an atomic fee reservation (25/day, 0.005 test ETH/day, 0.001 per transaction). Retraction cannot supersede an unresolved signed operation. The relay can reconcile existing signed bytes after deletion; deletion after a live publication lease cannot promise to stop the transaction.

Store APIs additionally provide artifact lists, pending-publication lists, reviewed retraction and expiry cleanup. Cleanup fences runs older than 300 seconds, removes expired artifacts and private case contents, expires review snapshots and trims audit events after 90 days. The online scheduler and dispatch/relay callers are implemented by the parent task.

Follow-up review also added lazy 300-second expiry on reads/admission, final queued cancellation, local-only unsigned retraction, eligible pending-publication filtering, consent schema/TTL hashing and immutable submission fingerprint checks. See `scamwin-integration-review.md` for the findings and resolutions.

The final indicator APIs use the existing indexed table with only owner-scoped HMAC fingerprints of hostname, recipient and endpoint. Raw indicator values are blank. Writes require an active owned check and serialize a twenty-indicator cap; lookups exclude the current case, foreign owners, soft deletion and expiry. The parent’s correlation module creates the HMACs and evidence-linked related-case explanations.

No remote database calls, schema push, migrations, branches or commits were performed. The Web3 agent is separately checking the SQL adapter using an isolated local PostgreSQL engine; publication JSON token/fee parameters were fixed with explicit text casts following that check. A real Neon deployment still needs schema application and concurrent integration checks before enabling collection/publication. Memory tests establish domain behavior, not live PostgreSQL/provider behavior.
