# Isolated Vercel publisher replacement

The selected fully online, zero-spend deployment uses Vercel investigations. Trigger's organization restriction also prevents its planned publisher. Replace that adapter with a second, publisher-only Vercel Hobby project. This amends the earlier platform-wide Vercel signing ban: the signing key is permitted only in this isolated publisher project's Production secrets, never the main website, investigation environment, shared team variables or Preview.

The publisher exposes one authenticated native Node API, processes one database-approved pending operation per request, and reuses the existing relay, consent, nonce, fee, generation and publication guards. No browser-supplied calldata or destination is accepted. A dedicated 32-byte shared dispatch secret authenticates server-to-server POST; GET is allowed only for authenticated daily cron. The main website receives only the URL and dispatch secret, and selects this adapter explicitly with SCAMWIN_PUBLICATION_BACKEND=vercel. Existing Trigger publication remains optional and explicit. Never silently fall back to another host.

Package only the existing pure Node relay/store dependency closure with the native handler. A build step may copy those files into the publisher root; enable inclusion of source outside the root in Vercel. No Next.js app, Auth0 routes or investigation browser is deployed to the signer project. Keep 300-second max invocation, one operation per call and existing Base Sepolia 84532/zero-value/fee/transaction limits. Return bounded sanitized statuses. Daily reconciliation is online; verified reviewer reads may nudge it. Do not claim inclusion is finality.

Prepare dedicated owner and publisher test wallets in ignored local files. Funding is through free Base Sepolia faucet claims only. Contract deployment and publisher activation require explicit execution approval after public addresses and fee caps are reviewable. Never print private keys or put them in the main website. Add a deliberate activation helper with chain/owner/publisher/fee guards, and no signing on import or without an execution flag.

Verify unauthenticated requests cannot load the database/relay; arbitrary body/query cannot select calldata; one approved operation is processed; exceptions never leak secrets; main dispatch uses HTTPS without redirects; standalone build contains no credential values; activation rejects wrong chain/owner/cap. Keep the original production investigation demo functional while this separate component is prepared.
